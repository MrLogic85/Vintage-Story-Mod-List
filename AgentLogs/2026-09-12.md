## Investigated: SmithingPlus vs. Toolsmith "several tool heads to repair" report

User reported (in Swedish): when one metal tool breaks, several tool heads end up needing repair — suspected conflict between SmithingPlus and Toolsmith.

No relevant errors/exceptions found in `Logs/client-main.log`, `Logs/client-debug.log`, or the server logs — both mods load cleanly and no crash/warning mentions either mod near tool breakage. This is a config/design overlap, not a crash bug.

Root cause hypothesis, from inspecting `ModConfig/SmithingPlus.json` and the `toolsmith_1.2.19.zip` assets:

- SmithingPlus has its own broken-tool-head recovery feature (`EnableToolRecovery: true`, `DontRepairBrokenToolHeads: false`) that applies to any item whose *code* matches `ToolHeadSelector`: `@(.*)(head|blade|boss|barrel|stirrup|part)(.*)`.
- Toolsmith represents *every* tool head — any tool type, any material, metal or nonmetal — as a single shared item type/code, `toolsmith:tinkertoolparts` (`assets/toolsmith/itemtypes/tinkertoolparts.json`). The specific tool/material is stored in item attributes (via its `ModularPartRenderingFromAttributes` behavior), not encoded in the item code.
- Because `tinkertoolparts` contains the substring "part", it matches SmithingPlus's selector. So SmithingPlus's own anvil-based head-recovery/repair bookkeeping — which appears to key off item code — gets applied to Toolsmith's heads too, on top of Toolsmith's own dedicated head/handle/binding repair-at-Workbench system. Since all Toolsmith heads share that one code, SmithingPlus's recovery bookkeeping can't distinguish "this specific broken head" from "every tinkertoolparts item that happens to be damaged," which plausibly explains why breaking one tool surfaces several heads as repairable at once.
- Toolsmith's own MOD_DB.json entry documents only one SmithingPlus integration: disabling its internal "Smithing with Bits" system so the two don't duplicate bit-smithing. This `ToolHeadSelector` overlap isn't handled by either mod.

**Confirmed** via the mods' own pages (checked after the user asked whether the pages said anything):

- Toolsmith's page: explicitly "designed from the ground up to work alongside Smithing Plus" — its Workbench reforges broken tool heads using SmithingPlus's anvil recipes. Recommends lowering SmithingPlus's `BrokenToolVoxelPercent` to 0.4 (installed config currently has 0.8) so head-breakage is penalized accurately.
- SmithingPlus's page: has user comments reporting the *exact* symptom — "Broke a copper axe head, ended up with six broken copper axe heads in inventory" — with a moderator reply: "You have to disable Tool Recovery."

So this is a known community-reported bug, not just a local hypothesis. The specific culprit is SmithingPlus's `EnableToolRecovery` feature (distinct from the Workbench-reforging-via-anvil-recipes path Toolsmith relies on, which is unaffected by disabling it).

Remedy applied 2026-09-12 at user's request, editing `ModConfig/SmithingPlus.json`:
- `EnableToolRecovery`: `true` → `false` — the moderator-recommended fix for the duplication bug.
- `BrokenToolVoxelPercent`: `0.8` → `0.4` — Toolsmith's own recommended value for accurate head-breakage penalties (unrelated to the duplication bug, but a documented compat tweak).

Documented in MOD_DB.json: added to `open_flags`, and added/updated a `checked` entry (dated 2026-09-12) to both `smithingplus` and `toolsmith` mod entries citing the confirmed mod-page sources and noting the fix was applied. This is a personal ModConfig/ file (gitignored, not part of the tracked repo) — nothing to commit/push for this change.
