## ProtoException crash traced to Knapster 4.1.1 (and a correction)

**Correction to the section above:** the Knapster error is *not* on every launch. The earlier grep matched
Knapster's system names in the "Started systems" listing, not the error itself. Checking for the actual
`Failed to start system Knapster...` line shows that it appears only in the 20:26 server log. That was the second
world loaded in that game session, and it crashed. None of today's five first-world loads (19:18-20:08) has it.

This matches open Knapster issue #56 (github.com/ApacheTech-VintageStory-Mods/Knapster/issues/56): on a
second world load in the same session, `KnapsterAdminModMenu.StartServerSide` throws a NullReferenceException
(stale Gantry statics), its packet registration is skipped, and the client dies with `ProtoException:
Invalid wire-type` on the connecting screen. A full restart avoids it. This is very likely the cause of the
whole ProtoException series (09-17 to 10-12), not RAM. The first crash in the series was on 09-17, the day
Knapster went to 4.1.1. Workaround: restart the game fully before loading another world. No upstream fix
yet (4.1.1 is still the latest). Recorded in MOD_DB.json (knapster). No mod changes made.

The Vanilla Armory errors the user sees at startup are the ones analysed above (SpecializedBags Revived patch
typo plus VA's missing helmet textures), all harmless.
