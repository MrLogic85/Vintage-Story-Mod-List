## Full mod update check

User asked to update toolsmithweapons to 1.0.1, then broadened the request to checking all 53
installed mods for updates. Queried `https://mods.vintagestory.at/api/mod/<modid>` for every
installed mod (game version confirmed as 1.22.7 from `Logs/client-main.log`) and diffed each
mod's latest release against the version recorded in MOD_DB.json.

9 mods had newer releases available:

- **Pure patch/bugfix bumps, applied** (all tagged compatible with 1.22.7, no dependency or
  compatibility changes noted): A Culinary Artillery 2.0.0-dev.23 → 2.0.0-dev.24, BloodTrail
  1.2.5 → 1.2.7, Knapster 4.1.0 → 4.1.1 (backwards-compat build for 1.22.x), Pet AI 5.1.1 → 5.1.2
  (fixed dogs above generation 0 no longer attacking), Stone Bake Oven 1.3.8 → 1.4.0 (heat can now
  transfer directly from Controller to Baking/Cooking block), Weaponsmith 1.0.0 → 1.0.1 (admin
  sword blacklisted from tinkering - had no legitimate craft path), xLib Fork 1.0.37 → 1.0.38,
  xSkills Fork 1.1.1 → 1.1.5 (notably fixes a glue/XP duplication exploit from reheating hardened
  glue).
- **Alchemy 2.1.22 → 2.2.0-rc.11: flagged, not applied.** The RC migrates potion coating/projectile
  logic onto a new required dependency mod, Effectlib (~1k downloads, small/new install base).
  Asked the user whether to move to the RC track; they chose to stay on stable 2.1.22 for now.
  Decision recorded in MOD_DB.json's alchemy `checked` entry - recheck once 2.2.0 leaves RC status.

Bumped the 8 versions in MOD_DB.json (plus `checked` entries for alchemy's RC decision and
weaponsmith's 1.0.1 fix), ran `sync-mods.ps1` (all 8 downloaded and swapped cleanly, 45 mods
already up to date), regenerated README.md's version table, and pushed: `af363c8` (previous tip:

User pointed out mods.vintagestory.at's own page marks a "Recommended download" (2.1.22 for
alchemy) distinct from "for testers" builds, confirming the alchemy call was right, and asked
that this be the standing rule going forward. Added a new bullet to AGENTS.md: prefer the
Recommended/non-prerelease release over a tester build unless the tester build is required for
the installed game version. Noted that the mod API's release list has no explicit "recommended"
field - infer it from the version suffix (`-rc`/`-pre`/`-dev`/`-beta`/`-alpha`) or check the page
directly when ambiguous. Doesn't retroactively apply to mods already deliberately tracking a
prerelease channel with a recorded reason (A Culinary Artillery's dev track, SmithingPlus's rc,
Durable Better Prospecting's rc).

## Crash on load, turned out transient

First load of "metacalfs adventure lands" after the 8-mod update batch above crashed at 14:09:25
(`Logs/client-crash.log`) with `ProtoBuf.ProtoException: Invalid wire-type` right as player data
was being received after connecting. Investigated: no mod named in the crash line, server log
showed heavy tick-overload warnings (1220ms/4576ms ticks) right around the same time, suggesting
the heavy initial load itself rather than a data-schema mismatch from one of the updated mods.
Considered and ruled out xSkills's "HunterBag" slot rework (1.1.3) as the cause - the user's
"ButcherBag" is actually from the (unchanged) Butchering mod, not xSkills. User retried and the
same world loaded fine the second time - confirmed transient, no mod rollback needed.
