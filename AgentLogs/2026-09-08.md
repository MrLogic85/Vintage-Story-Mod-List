## Logged the refined Boat Autopilot crash theory

Continuing yesterday's investigation into two 2026-09-07 crashes (21:55:35 vanilla `BlockGroundStorage.GetRandomColor` NullReferenceException during map-chunk-image generation; 22:30:26 access-violation crash inside `coreclr.dll` itself, 34m51s apart). User pointed out both happened while not piloting a boat, which doesn't clear Boat Autopilot: string-inspection of `boatautopilot.dll` shows its steering/obstacle-probe tick logic (`OnClientTick`, `ShouldSteerThisTick`, `IsPilotingSeat`/`get_Engaged`) is clearly gated on actually piloting, but it also registers a persistent custom map layer (`RouteMapLayer` via `RegisterMapLayer`/`IWorldMapManager`) that lives and renders continuously regardless of boat status — the same subsystem crash #1 happened inside. Recorded this as a new dated `checked` entry on `boatautopilot` in `MOD_DB.json` (not `open_flags`, since it's a single-mod stability question, not a cross-mod conflict). Decision: keep the mod installed, keep watching, too low a crash frequency to test by removal alone.

## Found a much bigger, unrelated problem: recurring whole-system BSODs

User reported the entire computer crashed (not just the game), while Vintage Story wasn't even running (no game log activity since 22:30 the previous day). Checked Windows' System event log and WER kernel-crash report queue:

- **This morning's crash**: bugcheck `0x0000007e` (SYSTEM_THREAD_EXCEPTION_NOT_HANDLED) at 07:12, exception code `0xc0000005` (access violation) — a kernel-mode driver exception, not something a usermode game process can cause.
- **`C:\ProgramData\Microsoft\Windows\WER\ReportQueue`** holds 24 queued kernel-crash reports going back to **2025-01-29** (an 11-crash cluster that day across codes `0x109`, `0x3B`, `0x1E`, `0xA`), then 2 more on 2025-02-02, then a **14-month gap with zero crashes** (2025-02-02 → 2026-04-24) — suggesting whatever caused the January 2025 cluster was fixed at the time.
- Recurrence resumed 2026-04-24, roughly monthly through the summer (`0x193` ×3, `0x139`, `0x4E`, `0x7E` on 2026-08-29 — the same day as the openal32.dll app-crash entries the user pasted earlier in the Boat Autopilot conversation, though at a different time of day).
- **Sharp acceleration in the last 22 hours**: three separate unexpected reboots — 2026-09-07 09:20 (`0x1E`), 2026-09-08 02:01 (`0x139`), 2026-09-08 07:12 (`0x7E`, this morning's) — each a **different** bugcheck type.
- No `Microsoft-Windows-WHEA-Logger` hardware-error events in the last 14 days (doesn't rule out RAM — consumer non-ECC RAM errors often don't surface there).

A rotating cast of unrelated bugcheck codes (memory corruption, security-check failure, IRQL violation, uncaught driver exception) hitting the same machine, accelerating in frequency, is the classic signature of **failing RAM or a broader hardware/power-delivery instability** — not a single buggy driver (which would repeat the same code) and **not Vintage Story or any of its mods** (today's crash happened with the game closed). This reframes yesterday's two game-level crashes as likely symptoms of the same underlying hardware instability rather than a Boat Autopilot-specific bug.

Recommended to user: run Windows Memory Diagnostic (`mdsched.exe`) or MemTest86 overnight, check CPU/GPU temps under load, check for a BIOS/driver change around late April 2026 (when the pattern resumed) or late August 2026 (when it started accelerating), and back up important data given the crash trend. No mod/repo changes made for this — it's outside the scope of this repo.
