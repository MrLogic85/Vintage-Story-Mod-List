# 2026-09-06

## Durable Better Prospecting: broken icons/text — switched release page

User reported that BetterProspecting (installed as `betterprospecting_22.0.0-rc.1.zip`) worked functionally but showed raw untranslated lang keys (e.g. `BetterProspecting:mode--distance-long`, `BetterProspecting:reading--blocks-away`) instead of translated text, and a blank placeholder icon instead of the mode icon.

Diagnosis: extracted the mod zip and its `DurableBetterProspecting.dll`. The assets live under `assets/durablebetterprospecting/` (lang + icon SVGs), but the DLL has its Lang/asset domain constant hardcoded as the string `"BetterProspecting"` — a domain mismatch, so every `Lang.Get`/icon lookup at that domain fails and falls back to raw key text / blank icon.

Found an existing upstream GitHub issue (devpikachu/DurableBetterProspecting#1) reporting the same symptom, with a comment noting it only affects the download from mods.vintagestory.at/betterprospecting, not mods.vintagestory.at/durablebetterprospecting. User had already commented there themselves.

Verified by downloading both release zips (same version 22.0.0-rc.1) and diffing: `assets/` tree is byte-identical between them (checksum match on lang json + all icon SVGs); only `DurableBetterProspecting.dll` differs — the durablebetterprospecting-page build has the domain constant correctly set to `"durablebetterprospecting"`, matching its own assets folder. Root cause is a packaging step that swaps the DLL's embedded modid/domain per release target but copies the (unrenamed) assets folder unchanged into both zips.

Action taken: backed up `Saves/` to `AgentBackupSaves/2026-09-06/`, updated `MOD_DB.json` (modid `betterprospecting` → `durablebetterprospecting`, assetid 16293 → 29429, url updated, `checked` entry documents the root-cause analysis above), then ran `sync-mods.ps1` — it removed `betterprospecting_22.0.0-rc.1.zip` and downloaded `durablebetterprospecting_22.0.0-rc.1.zip`. 51 mods installed (unchanged count, one-for-one swap).
